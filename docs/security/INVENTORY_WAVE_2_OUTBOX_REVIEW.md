Status: core delivered in PR 625; main Quality and Security passed, web and worker deployed at b0d1e8db, ECS revision 334. Protected authority changes produce an immutable domain event, ordinary audit reference and durable outbox entry in their own transaction. Snapshots are restricted authority metadata with explicit field lists. Optional historical-ledger references carry organization_id; historical records are not relabelled as new events. The envelope exported to the worker contains IDs and enumerated/versioned metadata only. Logs omit snapshots, worker credentials, lease capabilities and raw service errors. The existing AWS region and provider remain unchanged.

The worker has no general audit-table access or event-append permission. Claim requires both an active authenticated account and an existing active worker credential. Completion additionally requires the account-bound, credential-bound lease capability; expiry/replacement and credential revocation deny completion. Retries do not repeat a committed effect. SQL cancels only jobs whose current authority is invalid, records the denied decision and acknowledges in the same transaction. User DML, forged producer calls, foreign-account completion, stale lease and revoked-token paths are negative tests. Failure of producer/effect audit rolls back the associated mutation.

Existing external-publication commands wait for propagation after their normal authorization/representation/review gates. Tests prove denial while pending and normal operation after consumption. Ordinary reads keep synchronous access checks. The change does not claim universal read auditing or stage-22 retention/cache/search revocation.

The rollout must additionally verify journals, schema advisors, main CI, the exact deployed image and real polling. Alarm installation/verification is required and cannot be inferred from a log message or a successful ECS rollout. The OIDC role was observed to deny DescribeAlarms; an existing console session authenticated the CLI and installed/read back the four alarms without changing IAM.

Containment: synchronous authorization remains active even if the consumer stops. Failed/expired work remains durable and is alarmed; dependent publication fails closed. A rollback image without the consumer is not an acceptable steady state after enabling the propagation barrier. Repair is a forward-compatible consumer deployment or an explicitly reviewed database correction. No audit/history deletion is a rollback procedure.
